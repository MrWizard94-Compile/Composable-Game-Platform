# ADR 0014 — Host accounting, log retention, and third-party guests

**Status:** Accepted.

## Decision

A guest reservation is one hold. It is charged when the binary has passed inspection and before the worker is spawned, and it is refunded by that hold's flag. `release` and a failed load may both observe the same hold. The second refund does nothing. `release` does not subtract a session total that a concurrent refund also subtracts.

`release` marks the session closed, cancels calls already waiting on a worker, and then waits until in-flight loads and hooks have finished their own cleanup. The worker is inserted into the session before that wait, so a worker spawned during the load is terminated before `release` resolves. `dispose` is the same wait for every open session, and it is single-flight. A session opened after `dispose` runs no guest.

Host `maxMemoryBytes` is the sum of declared linear-memory maxima, in bytes, across every composition on that backend, including a load that has not finished. It is not process RSS. `isolateHeapMb` is not added to it. Composition `maxTotalMemoryBytes` uses the same unit for one session. Guest count and binary size follow the same in-flight rule. Host hook time stays cumulative.

Log caps are UTF-8 bytes. The per-line cap applies to the message. The byte cap applies to the stored line, including the module prefix and the single `[log dropped]` marker. `maxLines` counts stored lines, and the marker is one of them. Adding the marker never pushes the buffer past `maxBytes` or `maxLines`. Older lines are removed until the marker fits both. If the marker cannot fit, it is not stored and lines that already fit stay. `maxLines` of 0 stores nothing. Completed sessions keep their logs only up to `maxRetainedSessions` (default 8) and `maxRetainedBytes` (default 16384). Live sessions are outside that retention cap. A discarded session's `takeLogs` returns nothing.

An in-flight call is counted before its work starts. If that work throws synchronously, the count still drops when the returned promise settles, so `release` cannot wait forever. A value that is not JSON (`undefined`, a function, a symbol, a bigint, a non-finite number, a class instance, or a cycle) is refused before the guest runs. A getter or `toJSON` that throws is the same refusal, reported as `ABI payload is not JSON (could not encode).`, and the thrown value is not forwarded. The call or the hook fails, and the reservation is still refunded when the session releases. A worker `error` event and a time limit stop that guest the same way. `dispose` during any of those waits for the in-flight count, then terminates the workers.

An ABI handle is a host-minted object, not the JSON fields `{ "abi", "moduleId", "contributionId" }`. Only the composition that minted it can call it. A lookalike contributed by another module, a structured clone, and a prototype that points at a real handle are not callable. A real handle passed to another composition fails with `ABI handle belongs to another composition.` and does not enter either guest. A call with no arguments sends `arg: null` and `args: []`. An explicit `null` is `args: [null]`. An explicit `undefined` is refused. Guest JSON is copied with data properties, so a `__proto__` field cannot change `Object.prototype` or make an inherited `dispatch` into a handle.

`maxMemoryBytes` limits one guest's declared linear memory. `maxBinaryBytes` limits that guest's file. A policy that omits `maxBinaryBytes` uses the backend default, 65536, and does not inherit a previous composition's cap. `maxTotalBinaryBytes` and the host `maxBinaryBytes` remain sums. The worker checks the file against the binary limit and the memory against the memory limit.

`scripts/build-wasm-module.ts` compiles a folder whose `guest.json` lists contributions into `module.wasm`. An author who uses another toolchain omits `guest.json` and ships `module.wasm` plus `manifest.json` and no `module.ts`. `scripts/check-wasm-module.ts` validates that package and instantiates it on the Node isolate. It refuses a package that is not WebAssembly, that imports anything except an allowed `cgp.abi.log`, whose register result is not the contribution JSON, or whose file exceeds the binary cap while its memory maximum does not. The check disposes its backend even when instantiation throws. `scripts/browser-wasm.ts` loads the shared runtime in Chromium and composes a guest through `createBrowserWasmBackend()`. The foundations workflow installs the declared development dependencies, then Chromium, then typechecks. Typecheck does not run before those packages exist.

## Consequences

A second composition cannot borrow a host memory slot that a pending worker still holds, and a release cannot drive the ledger negative. Copy `examples/third-party-module` for a declarative guest, or replace `module.wasm` with the output of another compiler and run the check script. The browser test is a real worker, not the Node worker behind a fake `Worker` constructor.
