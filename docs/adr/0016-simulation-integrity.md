# ADR 0016 — Simulation integrity

**Status:** Accepted. This is not a transaction manager for arbitrary module memory.

## Decision

The Simulation Ledger is the authority for positions and the tick. Every commit, including a direct `callService` on `sim.commit`, has to be an open step, the next integer tick, the same entity ids in the same order, and integer coordinates in the inclusive range 0 through 1000. Seed and save use that same range. A check that fails does not change the tick or the positions. Abort clears the open mark and does not roll a commit back. Shutdown clears the open mark and does not commit.

Direct open, abort, and commit are an authorized way to change the ledger. The host has no caller identity, and in-process JavaScript is not a sandbox, so the runner is not a privileged principal. The pipeline is not required for a state change. What the runner adds is the proposal fold and exactly one completion event after its own commit. A direct commit does not publish. While a step is open, a second open is refused. A direct commit may finish that open step when the payload is valid, and then the runner does not commit again and does not publish. An invalid direct commit changes nothing and leaves the step open.

`advanceSimulation` and `seedSimulation` share one lane with `restoreSave` for that composition, in the order the calls were made. A step does not commit during a restore that started first. A restore does not write during a step that started first. The runner opens the step before the pipeline and aborts that mark if it does not commit. Two calls for the same tick produce one commit. Two calls for the next ticks, made in tick order, both commit, with no skipped or duplicated tick. A later tick submitted before the next one is refused, and the tick does not jump. A direct seed while a step is open is refused and adds nothing. A seed made through the runner waits, then follows the closed-seed rule if the step committed. A direct open does not take the lane. A restore during that open mark still runs, the ledger refuses it, and the host puts every written slice back. Completion is published only after the runner's own commit succeeds. A refused step publishes nothing. A subscriber that throws is named on the step result and does not roll the tick back. `publish` still calls the other subscribers. If `publish` itself refuses, the tick stays committed and `completion` carries the reason. That is not listed as a subscriber failure. A completion subscriber, and `importState`, must not call `advanceSimulation`, `seedSimulation`, or `restoreSave` on that composition. That call would wait for the operation that is waiting for it.

A system on `sim.systems` receives a snapshot and returns a proposal. It must not write the ledger, and it must not keep its own state during that call. The host does not roll back a scratch variable a system changes before a later system fails. The supported place to record a committed step is `sim.completed`, which runs only after the ledger accepts the step. A completion subscriber must not call `advanceSimulation`, `seedSimulation`, or `restoreSave` on that composition. That call would wait for the operation that is waiting for the subscriber.

Save and restore still use the slice document. The open mark is not saved. Restoring while a directly opened step is still open is refused by the ledger, and the host puts back any slice that restore already wrote, so another module such as the witness does not keep the rejected document. A restore and a runner step do not overlap. The same inputs, including after save and restore, produce the same ledger on the Node isolate and in a browser isolate. The proof composition is mixed: movement is JavaScript, and the boundary is WebAssembly.

## Consequences

There is still no prepare, commit, and abort protocol for module-local memory. A system that needs memory across steps listens for completion, or it waits for a later milestone. Physics, rendering, and a self-running clock stay out of scope. The 0 through 1000 range remains a contract of these modules, not a general spatial model.
